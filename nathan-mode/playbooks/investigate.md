# Investigate

**You own the answer**. Plan, route, then write.

Investigation requests are read-only. They produce a cited explanation or recommendation, not a code change.

1. Route through the **how** skill. If motivation or intent is asked, also route through the **why** skill.
2. Produce the skill's doc (how: overview, key concepts, how it works, inputs/outputs, triggers and impact; why: overview, history, why it is this way now, impact of changing it). If the request is a decision between alternatives, prefer a recommendation with a tradeoffs table instead.
3. Apply the **unslop** skill to the reply if the routed skill has not already.

If the investigation precedes a code change, hand back to the user and re-route to the **bugfix** or **implement** playbooks.

**Reply**: the investigation output. For "are we sure" answers, include your real judgement with reasons. Push back if the premise is wrong.
